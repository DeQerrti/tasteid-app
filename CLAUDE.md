# TasteID

Личный «паспорт вкуса»: отзывы, избранное, тир-листы. Раньше был ещё и
сайтом, сейчас — настольное приложение на Electron (данные лежат
папкой на диске пользователя) плюс мобильная версия через Capacitor.
Владелец — не программист, поэтому решения по архитектуре и
формулировки в общении с ним держи простыми и объясняй, что где лежит,
а не предполагай, что он это помнит или может проверить сам.

## Архитектура фронтенда — важно прочитать перед правками в app/js

`app/js/*.js` и `app/js/routes/*.js` — это **классические `<script>`-теги
без модулей**, все на одной общей области видимости одной HTML-страницы
(`app/index.html`). Файл `app/js/config.js` объявляет `TYPE_LABELS`, файл
`app/js/reviews.js` его свободно использует — без `import`, просто по
имени, потому что оба выполняются в одном общем скрипте страницы.

Это осознанное и уже принятое решение: переход на ES-модули или
TypeScript **не нужен** — обсуждали и договорились не трогать. Не
поднимай это как «проблему» снова.

Из этого решения вытекают два правила, которые ОБЯЗАТЕЛЬНО соблюдать
при добавлении/переименовании любого файла или переменной верхнего
уровня в `app/js/`:

1. **Каждое имя верхнего уровня (`const`/`let`/`function`), которое
   используется в другом файле, должно быть в списке
   `sharedBrowserGlobals` в `eslint.config.js`.** Без этого ESLint
   (`npm run check`) упадёт с `no-undef` на первом же использовании —
   и это правильно, так и должно быть: список — единственное место,
   где виден весь набор «общих» имён проекта.
2. **Порядок `<script>` в `app/index.html` (и `app/add.html`) имеет
   значение.** Файл, который объявляет имя, должен подключаться раньше
   файла, который его использует. Перед тем как трогать порядок
   скриптов — проверь `grep -n 'src="/js/' app/index.html`.

Опасность здесь не в «не уследить за всей архитектурой», а в двух
конкретных ошибках, которые уже случались в этом проекте:

- **Совпадение имён** между файлами (два `const`/`function` с одним
  именем в разных файлах общей области видимости) — браузер падает с
  `SyntaxError` при загрузке страницы. Ловится немедленно любым живым
  тестом в браузере (`npm run test:browser` или ручной запуск
  `npm run serve` + открыть страницу).
- **Забытое имя в `sharedBrowserGlobals`** — ловится ESLint'ом
  (`npm run check`) при каждом пуше, не нужно держать в голове.

Так что реальная страховка — не «Клод должен ничего не перепутать по
памяти», а то, что обе ошибки выше **механически ловятся** проверками
до того, как код попадёт в прод. Роль ассистента — прогонять эти
проверки перед пушем и не обходить их (`--no-verify`, отключение
правил и т.п.), а не помнить всё вручную.

## Единый источник для встроенных типов медиа

Раньше список из 11 встроенных типов (аниме, манга, фильм и т.д.) был
продублирован в четырёх местах. Теперь единственный источник —
`MEDIA_TYPES` в `app/js/config.js` (ключ, подпись, склонения, цвет).
`TYPE_LABELS`, `TYPE_PLURAL`, `TYPE_COLORS` (в `app/js/stats.js`),
`TL_TYPE_ORDER` (в `app/js/tierlist.js`) и `TYPE_BUILTINS` (в
`app/js/routes/add.js`) выводятся из него. Новый встроенный тип
добавляется одной записью в `MEDIA_TYPES` — остальное подхватится само.

`TYPE_FILTER_ORDER` в `app/js/reviews.js` — исключение, оставлен
отдельным списком осознанно: у него свой порядок под фильтр вкладки
«Отзывы», не совпадающий с порядком `MEDIA_TYPES`.

## Резервные копии обложек (covers-backup/)

- Имя файла обложки присваивается один раз, при первой резервной копии
  (см. `slug` в `scheduleBackupCover`, `add.js`), и больше не меняется —
  меняется только расширение, если файл потом пересжимают. Значит,
  чтобы опознать «тот же файл» после операции над диском, нужно
  сравнивать имя БЕЗ расширения, а не путь целиком.
- Папка `covers-backup/` общая сразу на три источника: отзывы
  (`cover_backup`), «Любимое» (`image_backup`) и персонажи/тайтлы
  ВСЕХ тир-листов — встроенных «Персонажей» и любых своих коллекций
  (`cover_backup` у тайтла, `img_backup` у персонажа внутри). Любая
  массовая операция над этой папкой (поиск ничьих файлов, переименование,
  пересжатие) обязана сверяться со всеми тремя источниками разом —
  сверка только с отзывами уже дважды приводила здесь к реальным багам
  (ложные «ничьи» файлы у персонажей/любимого, а до этого те же файлы
  считались орфанами).
- Любая операция, которая меняет ИМЯ файла на диске (например,
  пересжатие с другим расширением), обязана в той же операции поправить
  ссылку на него в JSON (`reviews.json`/`favorites.json`/файлы
  тир-листов). Ровно эта проверка была пропущена в одной из прошлых
  версий («Сжать старые обложки», кнопку с тех пор убрали) и разломала
  обложки всем, кто ей воспользовался — почини по образцу
  `repairCoverReferences()` в `core/api.js`, если придётся писать
  что-то подобное снова.

## Сжатие изображений — sharp на компьютере, canvas на телефоне

`core/api.js` — общий файл для настольной версии и телефона, но
платформы разные: на компьютере есть Node (там сжатие через `sharp` —
нативный модуль на N-API, работает под Electron без `electron-rebuild`),
на телефоне только WebView внутри Capacitor (DOM и canvas есть,
нативных модулей нет и быть не может). Поэтому сжатие — необязательная
зависимость `compressImage`, которую передаёт вызывающая сторона:
`electron/image.js` (sharp) на компьютере, свой код на canvas в
`mobile/src/main.js` на телефоне. Если добавляешь в `core/api.js` новую
операцию над картинками, которая должна работать на обеих платформах —
веди её так же, через параметр функции, а не импортируй `sharp`
напрямую в `core/api.js` (телефон его не соберёт).

`electron-builder` не умеет отдавать нативные модули (`.node`) из
`app.asar` — для `sharp` это уже учтено (`asarUnpack` в `package.json`:
`node_modules/sharp/**`, `node_modules/@img/**`). Добавишь ещё один
нативный модуль — не забудь то же самое, иначе собранное приложение
рухнет при первом же обращении к нему (а не сразу при запуске, так что
заметить это можно не сходу).

## Проверки перед пушем

`npm run check` — обязательный минимум (линт, форматирование, i18n,
дубли функций, структурные проверки, юнит-тесты). `npm run test:browser`
— отдельный набор проверок в настоящем Chromium через Playwright
(жесты пальцем, синхронизация, мобильный мост) — не входит в `check`,
гоняется отдельно и в CI отдельным джобом, но перед серьёзными
изменениями в `app/js/` стоит прогнать и его.

## Прочее

  дополнительного подтверждения на каждый раз.
- Дубли отзывов (один тайтл, несколько отзывов с разницей только в
  сезоне/мелочах) — это осознанная фича, не баг. Не добавляй проверку
  на дубли отзывов.
