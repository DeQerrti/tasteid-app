# Android/Capacitor и мобильный мост

> Часть инструкции для ассистента; короткая главная — `CLAUDE.md` в корне репозитория.
> Читай целиком перед правками в `android/`, `mobile/src/` и любым кодом, который ходит по списку файлов/картинок на телефоне.

## Android/Capacitor: правки WebView — в MainActivity.java, не в layout XML

`android/app/src/main/res/layout/activity_main.xml` **никогда не
подключается** — `MainActivity extends BridgeActivity`, а
`BridgeActivity.onCreate()` (в самой библиотеке Capacitor) ставит
СВОЙ layout (`capacitor_bridge_layout_main`) и создаёт `WebView`
программно, ещё до того как наш код успевает что-то сделать. Правка
`activity_main.xml` (например, `android:scrollbars="none"`) в v0.6.30
не сработала именно по этой причине — файл просто никогда не
инфлейтится, две сборки подряд ушли с фиксом, который ничего не делал.

Любая настройка самого WebView (scrollbars, настройки рендеринга и
т.п.) идёт в `MainActivity.java`, **после** `super.onCreate(...)`,
через `getBridge().getWebView()` — только тогда WebView уже создан и
доступен.

## Мобильный мост (Capacitor Filesystem) — только пачками, никогда разом

На телефоне обращение к файлам идёт через нативный мост Capacitor, и
он не любит сотни одновременных запросов сразу — реально вешает
список/страницу на секунды, а не просто "чуть медленнее, чем на
компьютере". Это уже дважды приводило к настоящим зависаниям в разных
местах `mobile/src/main.js`: при первой загрузке большого списка
(решено `imgObserver`/`rootMargin`, резолвит только видимое) и при
резолве уже закэшированных путей (решено `queueCachedResolve` +
`window.__mobileForceResolveImages`, пачками по 12, а не все сразу).
Любой новый код, который проходится по большому списку картинок/файлов
на телефоне, обязан использовать этот же пачечный паттерн, а не просто
`Promise.all` по всему списку.

## Регистрация разработчика у Google (с 2026–2027)

Google требует, чтобы у приложения, которое ставится не из Play Маркета, был
зарегистрированный разработчик (Android developer verification). Включается
на «сертифицированных» телефонах — с сервисами Google: с 30 сентября 2026 в
Бразилии, Индонезии, Сингапуре и Таиланде, с 2027 — везде. Google проверяет
только личность разработчика и связь «имя пакета + ключ подписи», а не
содержимое приложения. Причина, которую называет Google, — вредоносные
программы: по их данным, среди APK из интернета их в десятки раз больше, чем
в Play Маркете.

**Решение owner'а (ноябрь 2026):** пока не регистрироваться, денег не тратить.
Для пользователей — инструкция обхода в README («Android: «приложение от
непроверенного разработчика»»): «расширенный режим» на телефоне (один раз,
сутки ожидания, потом «насовсем» — иначе не встанут обновления) или `adb
install -r` с компьютера (ADB под ограничение не попадает). Телефоны без
сервисов Google не затронуты.

Если понадобится регистрация:

- **Бесплатно — аккаунт «ограниченного распространения»** в Android
  Developer Console: только почта, без документов и оплаты, но приложение
  ставится максимум на 20 устройств (Google называл и цифру 50 — сверить),
  владельцы которых приняли приглашение. Хватит owner'у и знакомым, не
  хватит для раздачи всем.
- **Полный аккаунт** — разово около $25 и документ, удостоверяющий личность;
  устройств без ограничений.
- Для любого из них нужны: имя пакета `ru.tasteid.app` (`capacitor.config.json`)
  и ключ подписи из секретов CI — копия есть у owner'а (`docs/security.md`).
  Ключ менять нельзя: зарегистрированная пара «пакет + ключ» и обновления
  поверх держатся на нём.
- Не обход: F-Droid берёт только открытые приложения (у TasteID лицензия
  закрытая), Obtainium ставит через тот же системный установщик и под
  проверку попадает так же.
