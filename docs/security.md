# Безопасность

> Часть инструкции для ассистента; короткая главная — `CLAUDE.md` в корне репозитория.
> Читай целиком перед правками синхронизации, ссылок, подписи Android.

## Безопасность: токен синхронизации, ссылки, ключ подписи Android

- **Токен GitHub для синхронизации на компьютере не хранится в
  `localStorage`.** `electron/main.js` шифрует его `safeStorage` и кладёт
  в `sync-tokens.json` в папке профиля (`userData`), по ключу на
  хранилище. Странице он приходит только в памяти — строкой
  `window.__TASTEID.syncToken` при загрузке (`injectEnv` в
  `electron/protocol.js`; HTML с токеном отдаётся с `no-store`).
  `app/js/sync.js` держит в `localStorage` конфиг без токена и сам
  переносит туда старые токены. Где шифрования нет (телефон, Linux без
  связки ключей, `scripts/serve.js`), маршрут `/api/app/sync-token` не
  отвечает `secure: true`, и токен остаётся в конфиге, как раньше. Не
  возвращай токен в `localStorage` на компьютере и не пиши его в логи.
- **Внешние ссылки — только `http(s)`.** `setWindowOpenHandler` в
  `electron/main.js` пропускает в `shell.openExternal` только их
  (`isWebUrl`). Ссылки приходят из импорта и синхронизации, а
  `openExternal` с `file://` или системными схемами умеет запускать
  программы.
- **Ключа подписи Android в репозитории нет и быть не должно** —
  репозиторий открытый. Раньше там лежал `debug.keystore` с
  общеизвестным паролем; с 0.7.3 он удалён, `*.keystore`/`*.jks` в
  `android/.gitignore`. CI собирает `assembleRelease` и подписывает его
  ключом из секретов репозитория: `ANDROID_KEYSTORE_BASE64`,
  `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
  `ANDROID_KEY_PASSWORD` (заданы; копия ключа есть у owner'а). Без
  секретов шаг «Ключ подписи» падает сразу. Ключ менять нельзя: другой
  ключ — и обновления перестанут ставиться поверх. Переход с отладочного
  ключа на свой в 0.7.3 разовый: старую версию на телефоне нужно один
  раз удалить (это написано в README).
